# Demo Data Truthfulness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make synthetic records, calculated values, forecasts, and unavailable status clear throughout VenoTrack without implying real-world data or service health.

**Architecture:** Keep the existing fictional seed and APIs. Correct unsupported UI claims, derive refresh information from actual successful query state, clearly mark map coordinates and seed data as illustrative, and remove arbitrary values generated by the UI. Update user-facing documentation to match.

**Tech Stack:** React, TypeScript, CSS, FastAPI, SQLAlchemy, seeded SQLite/MySQL-compatible demo data, Markdown.

**Spec:** `docs/superpowers/specs/2026-10-15-demo-data-truthfulness-design.md`

## Global Constraints

- Keep existing synthetic records so users can demonstrate inventory, risk, transfer, replenishment, and evaluation workflows.
- VenoTrack has no connection to e-Aushadhi, DVDMS, government production data, or live facility systems.
- Existing risk values are deterministic rule-based planning estimates, not predictions from a trained ML model.
- Do not invent operational numbers, contact details, verified dates, system health, or model performance.
- Preserve existing role-based access and ASV-only scope.
- Do not add automated tests or run test suites; run syntax/build checks and manually inspect the affected states.

## Review Focus

- **First dashboard load:** no successful query yet; show demo status without a fabricated “just now” time.
- **Delayed/error API response:** no “all systems operational” message; show neutral status or the existing error.
- **Map without verified coordinates:** map pins and straight-line distances must say positions/distances are illustrative.
- **New worker request:** do not create a planned arrival date by adding an arbitrary five days.
- **Evaluation with zero or synthetic labels:** sample size and limitation remain visible; no real-world performance claim.

## Files and Responsibilities

- `backend/app/seed.py`: remove plausible but non-operational facility phone numbers from newly seeded demo data while retaining workflow examples.
- `frontend/src/app.tsx`: shared shell status/footer, dashboard freshness, inert chart year selector, risk-page refresh wording, and worker request date submission.
- `frontend/src/Facilities.tsx`: label map positions and distances as illustrative; replace “live API data” with truthful synthetic-data wording.
- `frontend/src/GettingStarted.tsx`: keep role guide language consistent with synthetic data and rule-based planning estimates.
- `frontend/src/style.css`: style status and provenance labels consistently at desktop and narrow widths.
- `README.md`: describe synthetic, calculated, forecast, and unavailable values consistently with the UI.
